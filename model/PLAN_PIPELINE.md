# 工事計画生成パイプライン実装（CP-1〜CP-10）

作成：2026-11-10（サイドチャット「建築 工事 計画 手順 調査」）。CONSTRUCTION_PLAN_GENERATION.md の生成手順 CP-1〜CP-10 の実装記録。CP-0 とテーブルについては COST_TABLES.md を参照。

- 実装：`model/plan_generate.py`（使い方：`python3 plan_generate.py <建物モデル.json> [easy|normal|hard] [seed] [開始日]`、既定 2027-04-01 着工）
- 出力（ConstructionPlan 12ブロック＋検証結果）：`model/generated_construction_plan_game_mall.json`、`..._commercial_seeded2.json`、`..._commercial_seeded2_kameari.json`

## 実装した内容

- **CP-1 照査**：モデル側 gap（杭種別・支持層の未特定、EquipmentRun 未生成、延床目標値との差）を findings として根拠タグ付きで出す。計画データ側でごまかさず、扱い（仮置き＋見直し前提）を明記する。
- **CP-2 現場条件**：敷地占有率（資材置き場の制約）、隣地（住宅→作業時間と騒音配慮）、ゲート。
- **CP-3 基本方針**：DP-3 のとおり、ユーザーの入力は難易度（簡単／普通／難しい）だけ。査定率・バッファ率・歩掛の揺れ幅・工法の保守性は難易度レンジからシード抽選し decisions に記録する。
- **CP-4 工法・仮設**：揚重はラフター＋横引き（タワーは必要な場合のみ最大1基。本物件群は高さ45m未満のため不採用を decisions 相当に記録）、山留めは保守性で選択が変わる、足場は面別、仮設6項目を段階つきで出す。
- **CP-5 WBS**：WORK_STRUCTURE_V2 の構造でタスク生成。土工→杭→基礎（工区別・配筋検査ゲート）→躯体（節建方。建方日数は節の鉄骨量÷44t/日）→屋根・外装（面別レーン。面は立面の南・東・北・西に集約）→設備・内装（工区チェーン：墨出し→LGS→PS縦管→吊りボルト→空調→衛生→電気→ボード→設備2次→仕上げ→床→建具→器具付け→美装。高所作業車の階別搬入・搬出つき）→EV単独レーン→外構→試運転・検査群（自→監→施→法）→引渡し。日数は工区面積・階面積・面面積でスケールする（固定日数のままでは大規模物件で破綻するため）。
- **CP-6 日数・原価**：歩掛の揺れをシードでタスク別に抽選して適用（CP-0 で未適用だった分）。原価は CP-0 の金額項目をタスクへ配分（複数項目の配分に対応）。
- **CP-7 ネットワーク・暦**：CPM で ES/EF とクリティカルパスを算出。班の工区巡回は資源リンク（並行班数ぶん遡った工区へ接続）で表現し、職種別ピーク（山積み）を出す。暦は 4週8閉所＋長期休暇（年末年始・GW・夏季）で実日付化する。
- **CP-8 調達・検査**：長納期品目（鉄骨・キュービクル・EV・外壁材）に発注期限日を算出。検査チェーンは29件（基礎配筋×工区、水圧・隠蔽前×工区、鉄骨製品・建方、中間、受電、EV落成、消防、完了、竣工群）を書類→申請→実施で生成し、ゲートとして後工程に接続する。
- **CP-9 QCDSE・リスク**：QCDSE 計画（C は実行予算と S カーブ、D は CP とバッファ集約）、リスク5件（地盤 gap、梅雨・台風、近隣クレームは新工種開始時に増える、長納期、証拠不足）。
- **CP-10 検証**：PL-01〜PL-12 を自動判定し、結果を計画 JSON に同梱する。

WBS の実働日数は CP-0 基準値比で −9%／−1%／−9%。詳細ネットワーク（班の並行とパイプライン）を組むと集計レートより少し速くなる、という一貫した傾向で、3点推定の範囲内にある。難易度 hard（seed 7）でも 12/12 PASS し、バッファと実行予算だけが締まる（基準計画は不変）ことを確認済み。

## 検証で落ちて入力側を直した経緯（記録）

1. 初回は PL-09（原価の未配分：耐火被覆・型枠・鉄筋がタスクに紐付いていなかった）と PL-10（CP 718日）が不合格。原因は WBS 側で「内装」を1つの班として全工区を直列化していたこと——班を実際の下請単位（軽鉄・ボード・仕上げ・床・建具…）に分け、並行班数の資源リンクに変えて解消。
2. 面の集約前は、凹凸平面で外壁が載る軸ごとに「面」を作ってしまい亀有で外装が数百日に膨張（PL-10 不合格）。面は立面（南・東・北・西）に集約するのが正しく、修正後は全物件が範囲内に入った。
3. 工区・階・面の日数が固定のままだと大規模物件（亀有）で実態とずれるため、面積・鉄骨量によるスケールを入れた（CP-0 の出来高式と整合する形）。

## 後処理と統合手前パッケージ（2026-11-10 追加）

- **設備推論**：`model/equipment_infer.py` がシャフト配置（PS／DS）と部屋重心から系統経路を推論生成する（3物件で runs 213〜335件、全要素 inferred）。部屋は最寄りシャフトへ一意に割り当て二重計上を防ぐ。金額配分比は延長から出さない（系統ごとにネットワーク形態が違い単純比較できないため既定比 電気0.30／衛生0.22／空調0.48）。計画側の F-02 は gap から inferred（推論生成を使用）に格上げされた。モデル側で EquipmentRun が正式生成されたら差し替える。
- **山崩し提案**：`model/plan_postprocess.py` がフロート（後方パス）を計算し、職種ごとの同時並行が上限（班数）を超える日を検出する。提案はフロート範囲内の開始後ろ倒しのみで、適用しても総工期が伸びないことを再計算で確認したものだけを出す。3物件とも過集中 7〜10職種に対し提案4件が成立し、総工期は不変。フロートで解消できない過集中は「増班か工順変更の判断事項」として peaksAfter に残る。
- **ローリング詳細化**：同じ後処理で 3ヶ月工程（窓内タスク・週別山積み・検査の申請期限・調達の発注期限、作成＝所長＋課長）と 1ヶ月工程（日別の開始/終了・担当者TODO・申請期限、作成＝担当者、チェック＝課長）を生成する。着工直後の窓は準備・土工・杭の長いタスクが中心で、タスク数は 3ヶ月窓で10〜12件、1ヶ月窓で7件（序盤は内業と手配が中心という本編の設計感覚と一致）。
- **統合手前パッケージ**：接続仕様 `model/integration/PLAN_TO_GAME.md` と変換器 `model/plan_to_game.py`。DP-1 の換算（実働日→ゲーム日、durationScale 既定7）で3物件とも変換検証 PASS。ゲーム物件は全52ゲーム日となり、本編の既存バランス（計画43日・期限54日）と同程度の物量になることを確認した。本編側で決めること（予算単位の換算、タスク粒度の対応付け、ローリングの接続、難易度選択の置き場所）は仕様側に未決定として明示してある。

## タイムラプス側申し送りへの対応（2026-11-11、解像度ブラッシュアップ）

アイソメタイムラプス側の工種別深掘り調査（hidden_files/source_extracts/trade_deep_clusterA〜D）からの申し送りに対応した。タスク数は 286→317件（パークサイド）になり、PL検証は3物件とも 12/12 PASS を維持、実働日数は 363／483／538日（従来比 +1／+2／−1日）。

- **P1-1 室外機・受水槽**：屋上室外機チェーン（架台→搬入揚重→据付→冷媒配管ラック集約→気密→真空・保温・充填→試運転調整）と受水槽チェーン（基礎→パネル組立→引込接続→水張り→清掃消毒→水質検査・給水開始）を新設。給水開始と室外機試運転は総合試運転の前提に接続した。
- **P1-2 工法決定**：杭＝場所打ち（アースドリル）を仮定として明示決定（地盤 gap のため。既製杭埋込みを代替案として記録）。防水＝シート防水（塩ビ系・機械的固定）＋保護コンクリート、層構成7層を methods に記録し屋根タスクのサブステップにした。いずれも methods の決定記録に根拠タグ付き。
- **P1-3 重機配置計画**：計画ブロック `machineryPlan` を新設（10件：機種・台数・配置・在場期間をタスクの日付から算出。ラフター＋横引きが正、ポンプ車は打設日のみ、等）。
- **P1-4 搬入イベント**：計画ブロック `deliveryEvents` を新設（21件：生コン車は量と台数/日、鉄骨は t 数と車数、外壁パネル、鉄筋、キュービクル/EV/室外機/受水槽パネル、残土搬出）。
- **P2-5 サブステップ**：基礎（配筋→型枠→アンカーボルト確認／打設→養生→強度確認）、キュービクル（基礎→搬入→据付→接地→結線→試験）、冷媒（支持→ダクト→ろう付け→気密→真空→保温。充填は器具付け側）、EV（基ごとのステップ列と AS-07）、建具の二相分離（枠＝先付け／扉＝仕上げ後）、美装の2段化（中間→最終）、検査（実施→指摘→是正→再確認のループ構造を inspections.loop に明示）。
- **P2-6 待ちイベント**：サブステップに kind=wait/test を付けた（気密24h放置、水圧保持60分、パテ乾燥、シーリング硬化、床の養生・開放、舗装の50℃開放、消毒の30分放置、水質検査の結果待ち）。
- **P2-7 班編成**：`cost_tables.crewComposition` を新設し全タスクに crew（人数・役割・根拠タグ）を付与。舗装は国交省研究会の13名編成（出典付き）、揚重・鉄骨は玉掛け/合図者を必須配置、墨出しは2人1組。
- **仮定値の明示決定**：`cost_tables.assumptionValues`（AS-01〜AS-10）を新設し計画にも同梱した。軽鉄/ボード/床の㎡/人日、検査の指摘発生モデルと是正日数、足場の面数/日、EV 1基の日数、美装の総人日、水圧保持時間。いずれも「公表資料なし・調査未確認」の仮定値として basis を明記。
- **P3 の分担**：系統ツリーは equipment_infer の出力に雛形を追加（電気・衛生・空調、ノード数つき）。インサート割付けはデッキタスクのサブステップ化（割付け→合番確認→打設前最終確認）。開口台帳・パネル割付・目地ライン・建具/器具台帳は建物モデル側の分担とし、計画側は開口総数（651件）の集計だけを overview に持った。

## 残り・限界

- 本編ゲームへの統合そのもの（メイン側の判断事項）。
- P3 の台帳類（パネル割付・開口台帳・目地・建具/器具台帳）は建物モデル側の作業として残る。
- 検証はコード実行による数値・整合の確認のみ。工程の見た目（工程表として読めるか）は未確認。
