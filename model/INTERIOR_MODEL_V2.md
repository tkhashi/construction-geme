# INTERIOR_MODEL_V2 — 建物の内側をどう決めるか（生成器v2の方針）

作成：2026-11-08。経緯：seeded 生成 v1 の内側（バンド方式の汎用フィル）が「現実と乖離し過ぎている」とユーザーに却下された。フロアガイドは来場者エリアしか描かない、という指摘を受け、内側の決め方を3層に再設計する。

- hidden_files/source_extracts/ario_soga_whole_building_research.md（アリオ蘇我の全体像の再構成：事実と推定を分離）
- hidden_files/source_extracts/back_of_house_planning_research.md（用途別の非公開エリア：室プログラム・面積目安・配置ルール、法規／実務／慣行を区別）

## 1. 3層モデル

| 層 | 内容 | 情報源 | 確度 |
|---|---|---|---|
| L1 外形 | プレート形状・グリッド・規模 | PLATEAU／OSM のフットプリント（footprint_to_plate 変換） | 実測 |
| L2 公開部分の実像 | 階数、アンカーの位置と面積、モールの本数と走行、フードコート、ゲート位置、縦動線の位置 | 公式フロアガイド／駅構内図／施設概要（店舗面積・階数） | 公開資料（来場者エリアのみ） |
| L3 非公開部分の型 | 機械室・電気室・荷捌き・ゴミ置場・バックヤード・業務用EV・防災センター等の室プログラムと配置 | 建築計画ノルム（§3）で一貫して埋める | 型による推定（個別建物の正解ではない） |

原則：**L2 で読めるものは発明しない。L3 は「その建物の正解」ではなく「用途の型」として生成し、モデル上も推定であることを区別する**（部屋に source 属性：guide / program / inferred を持たせるのが望ましい）。

## 2. 面（フェイス）の読み — L3 配置の前提

建物の各面を、公開情報から性格付ける：
- **表の面**：ゲート（出入口）が集中し、駐車場・駅・大通りに面する → 来場者用開口、テナントの顔
- **サービス面**：来場者開口がゼロ〜最小の面 → 荷捌き・納品口・従業員通用口・ゴミ搬出を集約（L3 の核①）

アリオ蘇我の実例（調査済み）：
- ゲート9箇所：南面4／北面系3／西面1／**東面は地上階ゼロ** → サービス面は東面と推定（納品所の存在自体は施設利用規定で公式確認済み・7:30〜19:00開室・車両事前申請制。位置は非公開）
- 南＝車・バス・タクシーの受け口、北＝国道357・駅方面の歩行者口、という役割分担がゲート配置から読める
- 駐車場：屋上（モール側／ヨーカドー側の2ゾーン、車両出入口はすべて北面ランプ）＋平面第1〜第4（南東・南面中央・西面）。アリオ分1,650台

## 3. L3 の配置ルール（建築計画ノルムの要約）

配置の核5つ（詳細と出典は back_of_house_planning_research.md）：
1. 搬入・ゴミ搬出は敷地裏側（サービス面）に集約し、来場者動線と交差させない
2. 業務用（荷物用）EVは荷捌きに隣接させ、全サービス階を同系統で結ぶ
3. 機械・電気・発電機室は近接集約。ただし電気室は水系室（ポンプ・水槽）の直上・隣接を避ける（漏水）
4. 防災センターは避難階（1F）または直上直下階・非常用EV近接（駅は駅務室併設が原則、マンションは管理人室がその縮小版でエントランス隣接）
5. 水まわりは最下階で水槽に直結。必要室は給水方式（受水槽／直結増圧／直結直圧）で変わる

確度の高い面積数字（他は慣行・出典未確認として扱う）：
- 防災センター 40㎡以上（総合操作盤の対象規模＝延床50,000㎡級〜で法規必須。それ未満は任意設置）
- 商業の荷物バース 3.0m × 7.7m／台。荷捌きの審査は立地法＝ピーク処理能力＋自治体条例＝台数の二重
- 廃棄物保管：大店立地法指針の原単位式＋自治体条例（延床3,000㎡前後〜）
- マンション：ゴミ置場 0.13〜0.25㎡/戸、防災倉庫 0.05〜0.1㎡/戸、受水槽＝1日使用水量の約1/2（いずれも自治体差が大きい）
- 非常用EVは高さ31m超のみ。低層SCには通常置かない

## 5. 生成器 v2 への落とし込み（実装済み 2026-11-08）

`generate_building.py` に `seeded2 <out> <conversion.json> <annotation.json>` を追加。アリオ分の annotation は `model/seed_annotations_ario_soga.json`（フロアガイドから目視注釈）。

1. annotation の内容：階数・階高、アンカー（東端 frac≧0.68＝イトーヨーカドー）、準核（NW=無印良品・SW=コジマ）、モール走行（行指定）、フードコート（客席行＋店舗行・対象階）、コート吹抜け範囲、コア位置（coreFracs＝エスカレーター位置）、ゲート一覧（site.gates に出力）、サービス面
2. L3 フィルの実装：東面サービス帯に納品所・荷捌き／ゴミ置場／ポンプ室／従業員通用口を1Fに配置し、帯に隣接して業務用EV＋階段のサービスコアを全階共通で置く。防災センターは1F南テナント帯、機械室・電気室は北バックヤード帯（ポンプ室とは東西に分離）。残りはバンドフィル（推定）：モールから離れた南の深い帯は駐車場に面する大型店として埋める
3. 部屋に source（guide 63室／program 22室／inferred 87室）を付けた。レイアウト図では枠色で確度を表す（黒=guide、橙=program、灰=inferred）：hidden_files/source_extracts/footprint_samples/plate_seeded2_layout_ario.png
4. 結果：172室・全検証PASS（seeded v1 と従来生成物の回帰も全PASS）。フロアガイドとの一致：2階建て、ヨーカドー東端ブロック、主モール1本、FC 1F中央南、準核両端、サービス東面。残る乖離：南の大型店帯は推定フィルの単調さが残る、北東の雁行部にアンカーの細切れが出る
5. 検証器への L3 チェック追加（2026-11-09 実施済み）：V-L3-1〜4（荷捌き↔貨物EVコア隣接、電気室×水系室の非隣接、防災センターは1F、荷捌きが外周に面する）を検証器に追加し、両棟とも PASS

## 6. 再現性検証（2026-11-08、2棟目：アリオ亀有）

「アリオ蘇我で手加減しただけではないか」を確かめるため、性格の違う2棟目（アリオ亀有：都市型・地上3階・売場面積約42,120㎡・外形はNW-SEの斜め軸で南面が曲面）で同じ手順を回した。外形は OSM（way 141028342）→変換 IoU 0.96、annotation は seed_annotations_ario_kameari.json、生成は seeded2 で 297室・全検証PASS。

再現できた構造（実フロアガイドとの照合）：
- 階数（3階）、イトーヨーカドーの東端ブロック（南東の張り出し含む）、主モール1本、フードテラス（1F・アンカー西隣）、サニーコート吹抜け（3F中央）、コア3箇所＋東端サービスコア、防災センター1F

再現性として確認できたこと：
- 手順（公開ガイド→annotation→seeded2）は建物が変わっても回り、構造の骨格は再現する。annotation 作成は1棟あたり目視で数十分の作業

見つかった限界・不具合（正直な記録）と、その後の対応（2026-11-09）：
1. **階別アンカー未対応** → **対応済み**：annotation に `levelAnchors`（階指定＋frac範囲＋列帯＋columnFree）を追加。亀有 3F に MOVIX亀有を再現し、無柱区画として L4 の柱例外にも連動
2. **南の深い帯のフィルが縦ストリップ化** → **対応済み**：大型店フィルを行バンド分解（高さ2行まで）に変更し、モール平行の横長な室になった
3. **アンカーの面積分割も縦ストリップ** → **対応済み**：split_area を格子状分割（split_area_grid）に置換
4. **annotation の重なりは人が解く必要があった** → **対応済み**：生成器側で優先順位を固定（サービス帯・コア > アンカー > モール・準核・階別アンカー > FC・フィル）。アンカーは主スラブ行のみを対象とし、段型縁の細片（行ラン2セル未満）も除外
5. **方位・対応付けは形状照合頼み** → **解決（2026-11-09）**：変換器が実方位ベアリング（orientation: +X端の方位）を出力し、annotation の `anchorSide`（実方位）＋`anchorSize` と `serviceFace`（実方位）を生成器がモデル端へ解決するようになった。亀有は anchorSide="E" で同一結果（全PASS・室数不変）を確認。蘇我は当初未解決だったが、証拠が揃い全面フリップで確定した：serviceFace=E（実方位）は生成器がモデル −X 端（南南東端）へ解決して荷捌きをそこに置く一方、アンカーはモデル座標指定で +X 端（北北西端）にあり、調査の「アンカー東端・サービス東面」と両立しなかった。よって annotation の L2 由来 frac・行をすべて180°反転（行は現行プレート16行で j→15−j）し、アンカーは anchorSide=E＋anchorSize=0.32 の実方位指定に切替えた。L3（防災・機械・電気室）の frac・行は生成器の配置ポリシーであって地理情報ではないため反転していない。反転後に生じた V8（同一店舗の分解フラグメントに戸がない）は、生成器に後処理 fix_doors（検証器 V8 と同判定で検出し、境界壁の空き区間に戸を足す）を追加して解消。全検証PASS、蘇我は 230 室（反転前の 220 室から行ミラーの修正で変動）

生成図：footprint_samples/plate_seeded2_layout_kameari_1f.png / _3f.png、実ガイド参照：ario_kameari_floorguide_1F.pdf / _3F.pdf

## 7. L4：構造推論レイヤー（躯体は取得できない→推論で創造する）

ユーザー指摘（2026-11-08）：間取りだけでは工事にならない。建て方は躯体、特に柱位置で決まる。しかし柱位置は公開情報（外形・フロアガイド・施設概要）のどこにも出てこない。よって構造は「当てる」ものではなく、構造計画の実務原則から**推論して一貫したものを創造する**対象であり、各要素に推論の根拠を持たせる。基礎資料：hidden_files/source_extracts/structural_inference_research.md（数値の根拠の強さは【基準】【指針】【実務】【弱】で区別済み）。

### 7.1 現状の正直な限界

- 現生成器の柱は「グリッド交点に全部」で機械的。しかもシード変換のグリッド間隔は外形フィット（IoU最大化）で決まっており、構造モジュールとは無関係に選ばれている

### 7.2 推論の手順（L1–L3 の上に載る第4層）

1. **構造種別**：用途×階数×必要スパン → 商業低層大スパン＝S造【実務】、マンション〜5F＝壁式RC（法の適用範囲）／6F〜＝RCラーメン、駅上家＝S造（線路方向ブレース＋直角ラーメン）。階数帯の標準は東京都構造設計指針 表2.1【指針】
2. **構造モジュール**：商業＝駐車モジュール（車室2.5m×3台＝9m級、旧来2.3m幅では7m級）【基準＋実務】、マンション＝住戸モジュール（ラーメン柱間6〜9m）。外形フィットのグリッドとモジュールが合わない場合は、構造グリッドを引き直す（軸は共有し、柱を通す軸と通さない軸を分ける）
3. **柱の配置**：均等スパン・上下階一致を原則【指針】に、四隅・外周・区画境界・コア周囲・モール縁へ寄せる。車路・車室中央・搬入動線・大空間内部からは消す
4. **大空間の処理**：フードコート／アトリウム／シネマは内部の柱を消し、周辺柱を太くし、梁せい増（＝階高アップか天井高ダウン）を記録する。**岡立ち柱（長スパン梁の上に柱）は作らない**【実務】。上階の柱を受ける場合はトランスファー梁として明示
5. **部材寸法の初期値**：柱・梁は種別で描き分ける（RC：最大スパン8m・柱□750級／S：最大12m・柱□400級【業界資料】）。梁せい＝RC大梁 スパンの1/10〜1/12、S大梁 1/15〜1/20【実務】。スパン→梁せい→必要階高の連動で、階数推定（高さ÷階高）と矛盾させない
6. **耐震要素**：重心≒剛心（偏心率0.15以下【基準】が物差し）になるよう、RC＝コア周囲・外周・戸境ラインに耐震壁、S＝複数通りにブレース構面を分散。下階まで連続させる
7. **基礎**：形式は支持層深さ・地耐力・荷重規模で決まるが地盤は公開情報で確定不可【原則】。地形分類・液状化ハザード等の地域priorから `groundAssumption`（推定支持層・根拠付きの仮定）として保持し、確定情報として扱わない（地耐力の目安：20以下＝杭／〜30＝べた or 杭／30以上＝直接可、告示1347号の考え方【基準】）
8. **施工属性の導出**（ゲーム側への接続）：基準階面積→クレーン台数（1,200㎡/台【指針】、ただし50m以下はラフターのみ＝本編ルール）、S造→節分割（15m・3フロア以下）、RC→打設工区（ポンプ1台150㎥・面積300㎡目安）とサイクル（中層1フロア2〜4週／高層PCa 6〜8日）。柱グリッドの規則性＝型枠転用率＝サイクルの安定性

### 7.3 データ表現（スキーマへの提案 → v0.5 で実装済み 2026-11-09）

- 建物直下に `structure` ブロック（system＋根拠、モジュール根拠、柱断面・大梁せいの初期値、seismicElements、columnFreeZones、groundAssumption、constructionDerived）を追加 — BUILDING_MODEL_SCHEMA v0.5
- 柱を抜いた位置は Grid.columnExceptions に {at, levels, reason} で列挙し、無柱区画（columnFreeZones）側に treatment（大梁／トラス／受替）と根拠を持つ
- 耐震要素は structure 内の seismicElements（kind=ブレース／耐震壁、direction、配置セル、levelRange）として保持
- 生成器に `attach_structure()` を実装し、商業（パラメトリック／シード）・マンション（同）・駅舎・駅ビルすべてに推論ブロックを付与。検証器に V22a〜d（例外↔無柱区画、岡立ち禁止、耐震要素の両方向配置＋L1連続、種別・基礎仮定の記録）を追加し、全生成モデルで PASS
- いずれも source タグと同様に「推論であること＋根拠」を落とさないこと。実構造が判明した建物では推論を実測で置き換える（L2 と同じ扱い）

### 7.4 試作（アリオ蘇我 1F、2026-11-08）

図：footprint_samples/structural_inference_soga_1f.png（柱・無柱化・ブレース構面のみのオーバーレイ試作。2026-11-09 にモデル JSON への書き込みまで実装済み — §7.3）

- 種別・モジュール：商業2階 → **S造**と推論。外形フィットで決まった 7m×6m グリッドは、旧来の駐車モジュール（車室2.3m×3台≒7m）と整合し S造の成立スパン帯に入る — フィットの都合のグリッドに構造的な説明がついた。柱□400級、大梁せい 350〜470mm（スパン/15〜20）
- 柱の寄せ：室がセル境界に沿うため交点柱は元々ほぼ境界上にあり、寄せの実効は小さい。推論が実際に効いたのは次の3点
- 無柱化：サンコート吹抜け内部の柱 4点を取り除いた（740点→736点）。フードコート客席は奥行1スパンの帯で柱が境界上に立つため無柱化しなかった — 実物でも FC 客席にグリッド柱が立つ例は普通にある。**決定（2026-11-09、ユーザー確定）：A＝現状のまま。FC客席は境界グリッド柱を残す（実物のFC事例に倣う）。モデル・生成器の変更はなし。この要判断項目はクローズ**（吹抜け・シネマ級は無柱化必須という線引きは維持）
- ブレース：外周にバランス配置（北5・南5・西2・東2ベイ）。重心≒剛心の方向付けとして置いたもので、計算による検証ではない
- 基礎：蘇我は海岸低地のため地域 prior で**杭基礎を仮定**として記録（確定情報ではない）
- 施工属性：高さ10.8m → S造の節は1節（15m・3フロア以下【指針】）、クレーンはラフター（本編50mルール）、工区（X方向3分割）は柱通りと一致

## 8. 生成系の拡張と歩行距離チェック（2026-11-09）

- **歩行距離チェック（V-U商5／V-Uマ5）**：検証器に近似BFS（プレート全セル通行可＋条件付き斜め移動）を追加したところ、核店舗内部に階段が無く大規模売場が軒並み超過（最大120m）になることが判明。生成器側に (1) 核店舗内部の専用階段の格子配置、(2) 深いプレートでの南側コア、(3) テナント帯のコア間隔の継ぎ目への階段のみコア、(4) パラメトリック商業の L 字形状での南端コア、を追加し、全モデルで上限（商業40m／マンション50m）内を確認。階段はガイドのエスカレーター位置だけでは足りず、実建物でも売場内に分散する直通階段をモデルが持つべきだという設計知見

## 10. シードと前提の監査（2026-11-10）

ユーザーの確認指示（推論プロセスがあるのは問題ない。それを明示できていることが重要。他に不足がないかよく確認して）を受け、生成器の全決定項目を「シードの事実／推論／生成器既定／未生成（不足）」に分類した。対処として、生成モデルに前提の一覧 `assumptions`（{item, adopted, source, basis, process}）を出すようにし、V24 で seedSpec 全項目に対応記録があることを担保した。

監査で見つけた実害のある不整合（いずれも同日修正済み）：
1. **亀有の敷地周辺が蘇我の使い回しだった**：seeded2 の site.neighbors／roads は蘇我の調査値（国道357号・フェスティバルウォーク）がコードに直書きされ、亀有にもそのまま出力されていた。→ annotation に `site` ブロック（neighbors／roads／siteAreaM2／polygon、いずれも {value, basis}）を新設し、シードがある建物だけが値を持つ形に変更。亀有は未調査のため空＋assumptions に gap と明示（周辺の調査は RESEARCH_PROCEDURE の対象として残る）
2. **亀有の屋根に「実建物は屋上駐車場」という蘇我の注記が付いていた**：屋根オブジェクトの kind／note が共通コードで決め打ちされていた。→ シードの roofUse で切り替える（蘇我＝陸屋根（屋上駐車場）、亀有＝既定のシート防水＋「シード不明のため既定」と注記）
3. **杭が null のまま**：groundAssumption で杭基礎と仮定しながら foundations.piles は全モデル null で、読み手が「杭なし」と誤読し得た。→ attach_structure が杭基礎の場合に piles へ規則（each-structural-column、種別・径・長さは未特定と明記）を書き込む

分類の要点（seeded2）：
- 事実（seed）：外形・階数・モール／コア／FC／ゲート配置・アンカー・サービス面・屋上用途と駐車場（蘇我）・敷地周辺（蘇我）・スプリンクラー前提
- 推論（inference、根拠と手順 §7.2 を併記）：構造種別・工法（在来仮定）・基礎形式（地域prior）・構造モジュールと柱配置・耐震要素・部材寸法・施工属性、L3 の裏側諸室配置
- 既定（default、assumptions に明示）：天井高（一般室3600／モール・物販4800）、外壁の種別未特定、屋根仕様（シート防水）、敷地ポリゴンの仮置き矩形、基礎寸法・スラブ厚等の寸法定数
- 不足（gap、assumptions に明示）：EquipmentRun（設備横引きルート）はシード生成では未生成（パラメトリック生成にも1本のみ）、亀有の敷地周辺・接道は未調査、蘇我の階高5400の原典は未記録

マンション（シード）にも同形式の assumptions を付けた：階数の出所（注釈／OSM building:levels／既定5階仮定＝高島平の最大棟）、構造種別は階数帯からの推論、住戸タイプ配分はシードなし（生成器の型）、敷地周辺は仮置き。駅（シード）は annotation 自体が任意で未整備（fareRow の既定55%・駅ビル階数＝全階数−1 は生成器の仮定で、文書 §8／§9 とコードにのみある）— assumptions 化は今後の課題として残す。パラメトリック生成（commercial／mansion／station／game）は建物自体が架空で、パラメータがコードと DOCUMENTS に明示されているため対象外とした

## 11. 一級建築士 設計製図試験の知識の転用（2026-11-10 調査）

ユーザーの提案（二次試験では用途ごとに間取り・レイアウト・動線が一般的な建築計画に則って語られている。その情報から事実シードを元に内部を推論できるのでは）を受けて調査した。原資料メモは hidden_files/source_extracts/ikkyu_sekkei_seizu_research.md。結論：**転用できる。ただし用途で効き方が大きく違い、集合住宅には強く効く／大規模商業にはチェックリスト止まり／駅舎にはほぼ効かない**。

要点：
- 試験の課題文は「部門｜室名等｜特記事項｜床面積」の要求室表を持ち、面積指定は 約／以上／計以上／適宜 の4種。配置階は特記事項に書かれ、隣接・直接行き来・外部から直接、といった関係指定も入る。→ この表形式そのものが「事実シードから内部プログラムを立てる雛形」になる（我々の annotation の室プログラム版として使える）
- 公式資料は手厚い：建築技術教育普及センターが 2016〜2025年の10年分の問題用紙・標準解答例（図面2案）・合格基準等を無料PDFで公開。ただし「計画の要点等」の模範解答は非公表（理由づけの公式文はない）、利用条件は個人利用以外の転載・複製禁止 → 本プロジェクトでは要約とリンクのみ保持し、PDF・図面は保存・再配布しない
- 出題用途 2015〜2025：集合住宅（2015・2021）、事務所（2022）、図書館（2023）、美術館（2019）、大学（2024）、庁舎（2025）等。商業施設の単独出題は1982年が最後、駅舎は出題記録なし
- 規模の限界：試験は延床2,000〜3,000㎡級が中心で、最大級の令和4年事務所ビルでも標準解答例で5,941.6㎡。数万㎡級とは1桁違い、線形拡大はできない
- 裏側の限界：近年の課題は運営管理諸室を「適切に設ける」と大括りに委ねる（令和5年図書館では運営諸室が一文のみ）。試験知識は裏側カテゴリ（管理・清掃・ゴミ・搬入・設備・防災備蓄）の存在チェックには有効だが、面積比率・完全な室リストは導けない。我々の L3 は従来の建築計画ノルム調査（§7・back_of_house 系）が本体で、試験コーパスは補強という位置づけになる
- 用途別の効き方：集合住宅＝住戸面積の階段（1K約25／1LDK約50／2LDK約75㎡）、基準階の反復からの戸数逆算、共用・管理・設備の標準セット（管理人室の受付窓、ゴミ保管庫15㎡以上、受水槽25・ポンプ15・電気10㎡級）まで実績が厚く、USE_RULES §2 の裏付け・補強に使える。事務所＝レンタブル比（全体65〜75％・基準階75〜85％）やコア形式が粗い検証に使える。大規模商業＝飲食部門の裏側の型（客席200㎡に厨房35・食品庫10・従業員休憩兼更衣室15㎡＋サービス用駐車場、外部から直接入れる）と運営カテゴリの存在チェックのみ。駅舎＝動線分離等の一般原則のみで、改札・駅事務・運転関係・容量計画は鉄道側の専門資料が別途必要（現行の USE_RULES §3 の出所はその専門側）

根拠タグの対応（提案として記録、未実装）：調査側の提案「要求室表明示／包括条項からの類推／コーパス外」の3段階は、我々の室 source タグ（guide／program／inferred）の program 内の強弱として読み替えられる。L3 の program 室に、根拠が「試験の要求室表に明示あり」か「包括条項ベースの類推」かを分ける細分タグを付けるかは、今後マンション生成の型を試験準拠に寄せる時にあわせて判断する。

## 12. 特記仕様書1頁相当の網羅（2026-11-10）

ユーザー指示（シード段階で、設計図の特記仕様書1ページ目に示されるような内容は網羅したい）を受け、annotation に3ブロックを追加した。各項目は {value, basis}、生成モデルは building 直下にそのまま保持し、全項目が assumptions に記録される（値あり＝seed／null＝gap「未収集」。検証 V25）。

特記仕様書1頁の棚卸しとシードの対応：
- 意匠の特記1頁＝工事概要（名称・所在地・敷地・用途・規模・工期・発注者/設計/施工）と法規条件（用途地域・防火地域・建蔽率・容積率・高度地区・日影規制）と適用仕様 → outline（名称・用途・規模は既存項目と併せ）＋ zoning が対応。適用仕様（標準仕様書の版・優先順位）は設計図書側の属性として対象外にした
- 構造の特記1頁＝構造種別・基礎形式・地盤条件・部材の基準 → 既存の spec（structureSystem／foundationType）と structure ブロック／groundAssumption が対応済み
- 設備の特記1頁＝受変電・給水・排水・空調・熱源・昇降機・防災の概要 → systems が対応（スプリンクラーは既存 spec.sprinkler）。この概要が埋まれば、未生成の EquipmentRun（§10 の gap）を系統テンプレートで引く入力にもなる

充足状況（2026-11-10 時点）：
- 蘇我：outline は所在地・用途・延床57,500㎡・開業2005年・運営が充足。建築面積・高さ・設計者・施工者は未収集。zoning は6項目すべて未収集（自治体の都市計画情報で確認可能）。systems は7項目すべて未収集（テナント募集資料・環境報告書に設備概要が出ている場合に拾える）
- 亀有：outline は所在地・用途・開業2006年・運営が充足。延床は未公表（売場面積42,120㎡のみ）のため null。zoning／systems は蘇我と同じく枠のみ

未収集項目は「無い」のではなく「枠を用意して未収集と明示」した状態で、収集でき次第 value を入れるだけでモデルと assumptions に反映される。マンション・駅のシードへの展開は未実施（次に寄せるなら駅の注釈形式定義と合わせて）。
