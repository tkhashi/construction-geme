# アイソメ・タイムラプスビュー仕様（工事計画連動）

作成：2026-11-10（サイドチャット依頼）。本編3Dとは別系統の、2Dアイソメ図ビュー。

## データの出どころ（捏造しないこと）
- 工事計画：`model/generated_construction_plan_game_mall.json` / `..._commercial_seeded2.json` / `..._commercial_seeded2_kameari.json`
  - サイドチャット「建築 工事 計画 手順 調査」で生成した ConstructionPlan（CP-1〜CP-10、PL検証 12/12 PASS、normal / seed 42 / 2027-04-01着工）。
  - タスク 286／217／286件。各タスクに ES/EF（実働日・小数）と暦日付 startDate/endDate、phase、trade、zone を持つ。
- 部材の出現時刻：`model/generated_scene3d_*.json`（scene3d/1.0）の events。
  - 各 member（box形状 x,y,z,dx,dy,dz・kind・task）の `place` イベント時刻 t（実働日）が、その部材の出現時刻。計画タスクの ES〜EF の中に部材が1つずつ並ぶよう展開済み（Scene3Dパイプライン S3D-1）。
  - `remove` イベントがある部材はその時刻以降消える：外部足場（scaffoldUnit）、基礎型枠（footingForm/gradeBeamForm）、山留め（retainingPanel）、仮囲い・仮設（tempFence/tempOffice等）、遣り方（batterBoard）。
  - `stock`（仮置き）は place の前段。アイソメでは place 時刻で本設位置に出現させる（仮置き表現は対象外と明記）。
- コンパクトデータ：`iso_timelapse/iso_timelapse_data.json`（2.5MB、生成スクリプト `prepare_data.py`）
  - buildings[3]：{label, overview, startDate, endDate, totalWorkingDays（362.3／481.0／538.6）, phases[], tasks[], kinds[], members[]}
  - members[] = [出現t, 撤去t（無ければ-1）, kind番号, x,y,z,dx,dy,dz, taskId]、画家のアルゴリズム順（x+y→z）にソート済み。
  - 検証済み：可視部材数は単調増加（パークサイド 例：10% 318 → 50% 1,423 → 65% 4,356 → 100% 7,721 ※撤去分を除く）。

## ビューに必要な要素
1. 物件切替：パークサイドモール（3階・362実働日）／アリオ蘇我（2階・481日）／アリオ亀有（3階・539日）。実寸・実際の雁行平面・実際の部材位置のまま（縮尺テスト用の小モデルにしない）。
2. アイソメ描画：Canvas 2D、等角投影（x軸 右下30°／y軸 左下30°／z 上）。南東側から見る（仮囲いの手前側は従来方針どおり邪魔にならない高さ・透明度で）。部材は kind 別に色分け（柱・梁＝鉄骨色、スラブ/デッキ、基礎・杭、外壁パネル、サッシ＝ガラス色、足場＝半透明、掘削・土＝茶系、内装・設備の細部は階スラブの色味変化でも判別できること）。建物が一斉にせり上がる表現は禁止：出現は member 単位の place 時刻どおり。
3. タイムラプス再生：再生／一時停止、速度 ×1／×5／×10／×20／×40、進捗スライダー（実働日 0〜総工期）で任意時点へ。スライダー操作中も即時再描画。
4. 計画連動の表示：
   - 現在日付（暦）：タスクの startDate/endDate から補間せず、実働日→暦は「その日に開始/終了する直近タスクの日付」か schedules の暦対応で表示。少なくとも実働日数と進捗％（実働日／総工期）は常時表示。
   - 現在フェーズ名（準備・仮設／土工事／杭／基礎／躯体・建方／屋根・外装／設備・内装／EV／外構／試運転・検査・引渡し。検査チェーンは通期で並行するので主フェーズ表示からは除く）。
   - その時点で進行中のタスク一覧（ES≦t＜EF、検査チェーンを除く主タスクを優先し、件数と代表タスク名を表示）。クリック/タップでタスク詳細（工種・工区・開始〜終了日）が出るとなお良い。
   - マイルストーン到達表示（schedules.milestones：杭完了・第1節建方・受電・EV・引渡し等）。
   - フェーズ帯（工程バー）：phases の ES-EF を帯で示し、現在位置マーカーを置く。計画そのものが見えること。
5. 表示切替：外部足場 ON/OFF、仮設・資材（temp系＋仮置き系）ON/OFF、内装・設備の細部 ON/OFF（重い場合の間引きは表示側で行い、骨格部材＝柱・梁・スラブ・基礎・外壁は間引かない）。
6. 凡例：kind 色の凡例、データ出典（工事計画サイドチャット生成・PL 12/12 PASS・seed 42）と「stock仮置きは未表現」「室外機・受水槽は計画側にタスクが無く未生成（Scene3Dの gap）」の留保を画面内に明記。

## 禁止事項（従来のユーザー訂正）
- 一回の搬入・一括で建物全体が均一にせり上がる表現。
- 外接矩形（バウンディングボックス）での描画。部材 box は Scene3D の実座標そのまま使う。
- タワークレーンを複数立てる表現（計画はラフター＋横引き原則。クレーンを描く場合も1基まで、必須ではない）。
- 計画に無い工程・日付の捏造。日数・日付・タスク名は上記 JSON の値そのまま。

## 追補（2026-11-10）：重機レイヤー
- データ：コンパクトデータに buildings[].machines と lifts を追加（prepare_data.py 追補分）。
  - machines[] = {id, kind, label, keys:[[t,x,y,z]…キーフレーム], active:[[es,ef]…在場区間]}。在場区間は、その重機のキーフレームが属する計画タスクの ES/EF（高所作業車だけは搬入タスク開始〜搬出タスク終了＝その階に居る期間）。
  - 機種：ユンボ／ダンプ／杭打ち機／ポンプ車／ラフタークレーン／高所作業車（階別×2）／ユンボ（外構）／フィニッシャー／ローラー。位置はキーフレーム間を時刻で線形補間（端はクランプ）。
  - lifts[] = 部材の揚重イベント [t,x,y,z]（鉄骨建方タスク内 1,752／1,999／3,143件）。ラフター表示中は、直近の揚重先へブームを向け、ワイヤーと吊り荷を描く。
- 描画：重機は部材の後に画家順の乱れが無い形で描く（基本は最前面レイヤー、接地影付き）。アイソメで判読できるよう実寸より大きめに描いてよい（重機はリアリティの出しどころという既存方針）。種別が分かる形：ユンボ＝履帯＋旋回体＋ブーム、ラフター＝キャリア＋アウトリガー＋旋回体＋ブーム、ポンプ車＝車体＋打設側へ伸びるブーム、杭打ち機＝高いマスト、ダンプ＝荷台＋キャブ、高所作業車＝シザース＋作業床。
- 表示：重機ON/OFF切替（既定ON）を追加し、現在時刻に在場中の重機名をチップで出す（進行中タスク表示と並記）。
- gap（捏造しない）：Scene3Dに生コン車・搬入トラックのアクターは無い（stockイベントの注記「トラック搬入→仮置き」のみ）。このビューでも生コン車は描かず、ポンプ車のみとし、留保欄にその旨を明記する。
- 検証：重機が主役になる時点で目視する——土工事（ユンボ＋ダンプ）、杭（杭打ち機の移動）、基礎打設（ポンプ車・工区側）、建方（ラフターが揚重先へブーム＋吊り荷）、設備・内装期（高所作業車が階内に居る）、外構（フィニッシャー／ローラー）。最低限パークサイドで全区間、他2物件は建方時点を確認。

## 追補（2026-11-11）：担い手連動レイヤー
- 背景：部材・重機・人の3層が無結合で、「重機が来ていない所も土工事が進む／クレーンが運んでいない所に鉄骨が立つ／人がいない」とユーザー指摘。改修は prepare_data.py 末尾の coupling ブロック＋ビュー側描画。
- データ（prepare_data.py 追補3）：不変条件＝タスク・ES/EF・暦日・部材本数・座標・寸法・出現時刻の多重集合は無変更（スクリプト内でアサート）。
  - 人力主体タスク（基礎／屋根・外装／設備・内装／EV／外構／締め、鉄骨・揚重・検査・監督を除く）は、タスク期間内で出現時刻を空間スイープ順に再順序付け（種別グループ順は保持、remove 早期の部材は対象外）。
  - buildings[].fronts：タスクごとの作業前線サンプル（出現前線の重心、ES/EFキャップ付き）。
  - ユンボ keys＝掘削帯の掃引（帯ごとに走行、次帯への移動は次区間の25%）、ダンプ keys＝前線⇔ゲート往復。ユンボのブームはビュー側で「次に掘るタイル」を向く（数式アニメ廃止）。
  - lifts＝[揚重t, 部材index] に変更（本数は従来どおり 1,752／1,999／3,143）。クレーン keys＝揚重前線に沿う南北レーンの構え位置。
  - ポンプ車 aim＝担当打設タスクの前線サンプル（ビュー側でブーム照準に使用、敷地中心固定は廃止）。
  - buildings[].crews：タスク前線に沿う作業班（役割は工種・タスク名から：建方班／打設班／鉄筋班／型枠班／設備班ほか）＋ユンボ追随の誘導員。
- ビュー側：クレーンは揚重t〜place t の間、実部材そのものを実寸・種別色でワイヤー吊り（u<0.65 は粗い着地位置まで運搬、u≥0.65 はワイヤーを外して横引きで最終位置へ）。同時進行の他部材は横引き途中としてクレーン側へ最大1.8mずらして描く。固定寸法ダミー荷は廃止。作業員は班色ベスト＋白ヘルメットの人物グリフ（判読のため拡大表示）で前線に配置、「人を表示」トグル（既定ON）。内装・EV班は細部カリングと同じ条件で外装が閉じた階では描かない。
- 位置づけ：期間内の動きは計画データではなく「タスク期間内の作業順序の想定」である旨を、ビューの留保欄に明記済み。
- 検証（2026-11-11、プローブ再生目視）：パークサイド 36日（ユンボが掘削前線の縁、作業員4人/2班）、181日（クレーンが南レーンの建方前線脇、建方班4人）、250日（屋上・各階に作業員15人/5班）、362.3日=100%（外壁・屋根・パラペットの完成形に回帰なし）。蘇我250日（建方・クレーン＋建方班）、亀有50日（掘削前線にユンボ、作業員4人/2班）をスポット確認。20日は山留め期で計画上ユンボ不在、165/200日はデータ側シミュレーションで連動を確認（画面撮影は未実施）。

## 追補（2026-11-11）：人区算定・実人数投下・通過ルール
- 算定式：タスク人区（人日）＝ 1班人数 × 投入班数 × 期間（実働日）。1班人数＝model/scene_rules.json の global.crewByTrade（工種別ゲーム用既定）。投入班数＝計画の資源リンク並行班数だが、計画JSONの resource は全タスク None のため1班（上限 resources.tradePeak）。検証済み：1班/タスクで同工種タスクの最大同時並行数は全物件・全工種で tradePeak 以下（＝計画の資源モデルと一致）。工区分割タスクは計画上も別タスクで、工区ごとに投下。根拠は「計画テーブル由来の算定であり公表歩掛そのものではない」とページに明記。
- 結果：総人区 パークサイド 4,486 人日／蘇我 4,858／亀有 6,441。ピーク現場人数（作業者経路の有効期間で数える画面表示と同一の定義）47人@実働296.5日／35人@343.4日／51人@450.6日。
- データ（prepare_data.py 追補4）：tasks[] に crew/bands/nWorkers/personDays を付与。buildings[].workers[]＝作業者1人ずつの {task, role, keys}（旧 crews は廃止）。部材の無いタスク（監督・検査等）は建物周りの巡回経路。土工タスクの作業者1名は誘導員とし掘削タイルを担当。
- 通過ルール（絶対条件）：全ての部材を担当タスクの作業者1名に割り当て、その作業者の経路が部材重心を出現の0.35実働日前に通過するキーを持つ。生成時に全数 assert（対象 8,940／12,458／19,166 件、違反0件）、出荷データへの独立監査でも違反0件。部材の出現時刻・本数・座標は無変更（旧データと全行一致を照合済み）。
- ビュー側：作業者は1人ずつ個別描画。HUDと進捗欄に現場人数（投下実人数）を常時表示し、タスク詳細に投入班数・人数・人区を出す。外装が閉じた階の内装・EV作業者は姿を描かない（人数には数え、HUDに「うちN人は外装の内側で姿は見えません」と併記）。
- 検証（2026-11-11、プローブ再生目視）：パークサイド36日（ユンボが掘削前線の縁、土工作業者5人＝crewByTradeどおり）、181日（建方・クレーン、作業員6人）、290日（作業員34人チップ＝算出カウントと一致、外壁・屋根の完成形に回帰なし）、タスク詳細で投入・人区表示を確認。
